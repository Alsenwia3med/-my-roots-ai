ROOTS-AI™ C-03 Report Content & Visual Reference
Pack v1.0.1 - CONTROLLED CORRECTION
Document ID: ROOTS-C03-REPORT-001 | Controlled correction to v1.0.0
This correction sheet is an integral part of the attached v1.0.0 human-readable release and supersedes only the clauses expressly
identified below. All other approved report-content, safety, deterministic-data, privacy, accessibility and 19-section requirements remain in
force.
1. Linked dataset versions
Supersedes Section 1 - Linked datasets. The report implementation shall use C-01 v1.0.1 and C-02 v1.0.1. The canonical report JSON
shall store the actual questionnaire_version and scoring_version used for each report. No report may claim v1.0.0 when generated from
v1.0.1.
2. Visual authority and semantic colors
Supersedes Section 2 wherever fixed palette, typeface, spacing or component styling could be interpreted as final visual
authority. Classification labels, thresholds, accessibility requirements, numeric/text equivalents, page-size consistency, footer metadata
and non-stigmatizing imagery rules remain binding. Existing hex values, Inter/Arial references and the 8-point grid are semantic/legacy
implementation references only, not final UI tokens. Final colors, typography treatment, spacing, chart appearance, components and
visual hierarchy are governed by the approved ROOTS-AI Visual Direction and, after written ROOTS-AI approval, the PUB-01 Golden
Screen/design system. Visual styling must never alter score meaning, thresholds, content, accessibility or report parity.
3. Biological State identifier
Supersedes Section 4.3 placeholder. Use {biological_state_classification} for the Biological State label. The domain ID BS remains
exclusively Biological Safety Signals™. Implementations must not reuse BS as an identifier for Biological State™.
4. Driver cardinality and rendering
Supersedes Sections 4.2 and 4.6 wherever three drivers are assumed. The report shall render exactly the deterministic driver outputs
returned by C-02 v1.0.1: zero to three output entries. A co-primary pair is one output entry containing two domain IDs. Do not duplicate
a domain, invent a secondary/tertiary driver, or insert an ineligible/null/<25 domain to fill layout space. If no eligible driver exists, use the
approved no-dominant-burden copy. Executive Summary wording must adapt to the number of available driver outputs.
5. Biological Triad™ fallback
Supersedes Section 4.8 fixed three-item assumption. The Biological Triad™ may render only verified deterministic inputs. Preferred
inputs are available driver output(s) plus an actually present protective factor. If fewer than three eligible elements exist, use a reduced
two-element/one-element state or the approved Not Available state. No AI or template may invent a missing driver or protective factor.
Relationship language remains possible/potential, never causal.
6. Reference sample and version display
Supersedes Section 8 version references only. The sample remains illustrative and retains the shown numerical example unless
separately revised. Any displayed questionnaire/scoring/rules version must reflect C-01 v1.0.1 / C-02 v1.0.1 as applicable.
Report-template version is C-03 v1.0.1. Version metadata must be taken from canonical stored report JSON, not hard-coded.
7. Acceptance check RPT-04
Supersedes RPT-04. Every chart has a text and numeric equivalent, never relies on color alone, meets accessibility
requirements, and conforms to the written-approved ROOTS-AI Golden Screen/design system for final visual presentation. C-03
semantic colors do not override the approved final visual system.
8. Canonical JSON / null-state clarification
Clarifies Sections 9 and 10 without changing their intent. Drivers must be represented as the exact C-02 v1.0.1 deterministic output,
including zero-length arrays and co-primary structure. Missing driver/protective-factor data must remain explicit and must trigger governed
reduced/Not Available states; no imputation is permitted. Web and PDF continue to render from the same stored canonical JSON hash.
Integrity statement. This v1.0.1 correction does not change the 19-section report architecture, domain names, classification thresholds,
scoring mathematics, safety boundary, fixed medical/AI disclaimer, governed narrative limits, micro-action library, laboratory-discussion
boundary, web/PDF same-JSON requirement, or prohibition on diagnosis/treatment/medication advice.
Precedence. If the attached v1.0.0 pages conflict with this correction on the matters above, this v1.0.1 correction controls.

7. Governed Narrative Contract
 Input is an allow-listed explanation object containing pre-calculated values, classifications, driver IDs, eligible
content IDs and version identifiers.
 Q73 free text is sanitized, separately classified and never inserted into system instructions. It may be summarized
only when safe and relevant.
 Output is JSON matching the approved section schema; every section has a length limit and deterministic fallback.
 Required framing includes may, suggests, appears consistent with, possible or potential where causality is
uncertain.
 Prohibited: “you have”, “this proves”, diagnosis, cure, treatment, medication change, guaranteed outcome,
invented test result, invented fact or emergency triage beyond fixed approved text.
 One governed retry is permitted after validation failure; then the fixed fallback copy is used.
