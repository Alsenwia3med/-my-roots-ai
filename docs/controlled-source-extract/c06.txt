ROOTS-AI™ C-06 Executable Technical Baseline v1.0.1 -
CONTROLLED CORRECTION
Document ID: ROOTS-C06-TECH-001 | Controlled correction to v1.0.0
This correction sheet is integral to the attached v1.0.0 release and supersedes only the source-version, deterministic-export and
Golden Test authority statements identified below. All unaffected API, schema, database, RLS, ERD/role, security and
technical-readiness requirements remain binding.
1. Canonical executable-source versions
Where the attached release refers generically to C-01 and C-02, the executable data release shall be derived from C-01 Canonical
Question Bank v1.0.1 and C-02 Canonical Scoring Rules and Golden Tests v1.0.1. Their final approved XLSX files are the
canonical executable sources. Export metadata shall record the exact source filename/version and final SHA-256 checksum used
to generate each JSON/CSV artifact.
2. Question/scoring export integrity
The question/scoring JSON and CSV exports shall reproduce the approved C-01/C-02 v1.0.1 content and deterministic rules
without manual reinterpretation. Acceptance retains the canonical counts 73 questions / 13 modules / 40 scoring-eligible
questions, and the export source hashes must match the final controlled source files.
3. Golden Test authority
The executable Golden Test artifact may retain an implementation filename such as golden_tests.v1.0.0.json only if its embedded
release metadata identifies C-02 v1.0.1 as the canonical source; alternatively it may be versioned to match the controlled release.
In either case, all 30 tests must match the C-02 v1.0.1 canonical expected outputs exactly.
4. Deterministic driver requirements within the 30 tests
Exact Golden Test conformance includes the corrected deterministic driver behavior: eligible domains only, descending score
ranking, fixed tie order MR, HS, SR, CH, SL, IB, BS, co-primary behavior when the top two eligible scores differ by no more than 3
points, a co-primary pair rendered as one output entry, no duplication, no ineligible/null fallback and no LLM selection. The
BIO_STATE identifier represents Biological State; BS remains exclusively Biological Safety Signals™. Canonical rounding rules
from C-02 v1.0.1 also apply.
5. No architectural or commercial change
This correction does not alter the documented OpenAPI 3.1 contract, five JSON Schema 2020-12 files, three ordered SQL
migrations, eight required logical application tables, role assignments/contact enquiries, RLS on protected relations, 12 negative
RLS tests, research-consent requirement, HMAC-SHA-256 pseudonymization, Architecture Gate evidence, commercial baseline or
delivery schedule. It is a controlled source/version-integrity correction only.
Precedence: where the attached v1.0.0 pages conflict with this correction on the matters above, v1.0.1 controls.
