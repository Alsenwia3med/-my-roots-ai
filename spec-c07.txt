Acceptance v1.0.1 — CONTROLLED CORRECTION
Document ID: ROOTS-C07-TRACE-001 | Controlled correction to v1.0.0
This sheet is integral to the attached v1.0.0 trace release. The 594 source-record rows remain preserved for provenance. Where a
historical source statement conflicts with the final controlled implementation baseline, the canonical implementation and acceptance
interpretation below supersedes that historical wording; the historical wording is not an independent implementation authority.
1. Controlled-reference versions
Canonical artifact references shall resolve to the final controlled releases: Master Product Implementation Requirements v3.3.1
CORRECTED (subject to the final package-integrity update), C-01 v1.0.1, C-02 v1.0.1, C-03 v1.0.1, C-04 v1.0.1, Secure Kickoff v1.0.1,
C-05 v1.0.1 and C-06 v1.0.1. A legacy version label in an attached source-record row does not override these controlled releases.
2. SCR-0004 — Driver
Canonical implementation requirement: Driver output is determined only by C-02 v1.0.1. Eligible domains require a non-null score ≥25;
rank descending by score with exact-tie order MR, HS, SR, CH, SL, IB, BS. If the top two eligible scores differ by ≤3, they form one
co-primary output entry. Report zero to three output entries, with no duplication, no ineligible/null fallback and no LLM selection. The
historical phrase “the highest-scoring domain” is retained only as source provenance and is not sufficient implementation logic.
3. RPT-0026 / Q73
Canonical implementation requirement: Q73 remains optional free text, 0–1000 characters, sanitized, and must never be concatenated
directly into model instructions; allow_na=False. The attached legacy source-record value allow_na=True is superseded by C-01 v1.0.1.
4. Required multi-select validation
For every required multi-select question governed by C-01 v1.0.1, one or more approved option IDs are required; an empty array is invalid.
NONE/N/A is exclusive where provided and cannot be combined with other options. Acceptance tests must verify these negative cases.
5. UI-0001 — visual authority
Canonical artifact: C-05 v1.0.1 + ROOTS-AI Visual Direction + written-approved PUB-01 Golden Screen/design system. C-08 governs
editable asset handoff within its controlled scope. Existing SVGs are functional/content wireframes only and are not final visual authority.
Evidence remains required at 360/768/1024/1440 and must preserve accessibility and functional behavior.
6. LEG-0002 and legacy legal/compliance wording
Historical source phrases such as “HIPAA-ready” are preserved as source records only and do not constitute certification, legal status or a
universal PHI claim. Canonical implementation follows C-04 v1.0.1 and the controlled security/privacy baseline using PII/personal
data/health-related data terminology, with PHI/HIPAA treatment only where legally applicable. No implementation or marketing claim may
be inferred solely from the historical source wording.
7. Report / driver / Biological State traceability
Report acceptance shall use C-02/C-03 v1.0.1 exact deterministic outputs, including zero-to-three driver entries, co-primary as one entry,
reduced/Not Available states, and no invented driver/protective factor. BIO_STATE identifies Biological State; BS remains Biological Safety
Signals™.
8. C-06 executable evidence
Trace acceptance that depends on executable data, API/schema/database or scoring evidence shall use C-06 v1.0.1 and exports
generated from the final C-01/C-02 v1.0.1 canonical sources. All 30 Golden Tests must match the C-02 v1.0.1 expected outputs exactly,
including corrected driver, BIO_STATE and rounding behavior.
9. Coverage-status rule
A row marked “Covered” is accepted only when its canonical artifact and named test/evidence conform to the current controlled baseline
and this correction. The status label alone is not acceptance evidence. Historical rows that conflict with a later controlled correction are
covered only by satisfying the corrected requirement.
